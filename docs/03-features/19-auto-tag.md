# F19 视觉模型自动打标签

为全局素材库的**图像**调用具备视觉能力的大模型（如 DeepSeek-Flash 一类 OpenAI 兼容接口），按固定但可配置的提示词生成分组标签。提示词预置见文末；实现时原样放入 `packages/core/prompts/asset-auto-tag.zh.md`，设置里可编辑，可一键恢复预置。

相关：[04-assets](04-assets.md) · [架构](../01-architecture.md)

## 目标

- 用户自行配置视觉模型 endpoint、模型名、API Key（与 S3 一样：客户端直连，**零自建后端**）。
- 可配置打标签时机：加入素材库时、仅无标签时加入、手动单张、手动批量（未打/已选）。
- 模型只产出标签 JSON；客户端解析后写入素材 `tags`（检索用扁平串）与 `visionTags`（按维度分组）。
- **不覆盖用户手打标签**。再次跑模型时只替换 `source=vision` 的标签。

## 对象模型

### 本机：模型凭证（不上 S3）

```ts
type VisionProviderConfig = {
  id: string
  name: string                    // 如 "DeepSeek"
  endpoint: string                // 默认 https://api.deepseek.com/v1/chat/completions
  model: string                   // 默认 DeepSeek-Flash，可改
  apiKey: string                  // 安全存储；UI 只显示后四位
  apiStyle: "openai-chat-completions"
}
```

预置供应商档案只填 endpoint 与默认 model，**不含密钥**。

### 同步到远端：打标签策略与提示词（不含密钥）

`{prefix}.artstock/v1/settings/vision-tag.json`（持锁更新）：

```ts
type VisionTagSettings = {
  schemaVersion: 1
  enabled: boolean
  providerId?: string             // 本机 provider 列表中的 id，可空
  triggers: {
    onImport: boolean             // 加入素材库时
    onImportOnlyIfEmpty: boolean  // 为 true 时仅当尚无任何标签
    // 手动触发始终可用，无需开关
  }
  sendImage: {
    maxEdgePx: 1024               // 送模型前最长边
    jpegQuality: 0.85
    wifiOnly: boolean             // Pad 默认 true；桌面默认 false
  }
  prompt: string                  // 完整系统提示词；空则用预置
  updatedAt: string
}
```

各设备共享同一套提示词与时机，避免桌面与 Pad 打出两套口径。API Key 仍每机自配（可同一把）。

### 素材条目扩展

在 [04-assets](04-assets.md) 的 `AssetItem` 上增加：

```ts
type VisionTagGroup = {
  dimension: string               // 视角、构图、色调…
  tags: string[]                  // 短词，不含维度前缀
}

type AssetItem = {
  // …原字段
  tags: string[]                  // 扁平：["视角/俯视", "构图/三分法", "手打标签"]
  visionTags?: {
    groups: VisionTagGroup[]
    model: string
    taggedAt: string
    promptHash: string            // sha256(prompt) 便于知道是否用过旧提示词
  }
}
```

扁平规则：`tags` 含 `{dimension}/{tag}` 形式的视觉标签，以及用户手打的任意字符串（手打**不要**自动加维度前缀，除非用户自己写了 `/`）。

合并：OR-Set。重跑视觉标签时：从 `tags` 去掉旧的 `dimension/` 前缀项，再写入新组；手打项保持。

### 送模图像

优先：已缓存原图 → 缩放到 `maxEdgePx` 的 JPEG。若只有缩略图，可用缩略图但在 UI 标「低清打标」。不把 PSD/CLIP 等非栅格文件直接塞进 API；无法栅格化则跳过并记失败。

## 时机

| 时机 | 行为 |
| --- | --- |
| 加入素材库 | `triggers.onImport` 为真时入队；`onImportOnlyIfEmpty` 时仅 `tags.length===0` |
| 手动 · 单张 | 详情页「AI 打标签」 |
| 手动 · 已选 | 多选后批量入队 |
| 手动 · 未打标签 | 扫描素材库中无 `visionTags` 或 `tags` 为空者 |

队列串行（避免打爆限流）。暂停同步不等于暂停打标队列，但离线/无 Key 时失败并留在队列。打标完成后再把 meta 变更交给同步队列，**写 S3 仍走全局锁**。

未配置 Key 或 `enabled===false`：导入不调用模型，手动按钮提示去设置。

## UI

- 设置 → 「视觉模型」：供应商、endpoint、model、Key、探测（发一张 1×1 像素或厂商 models 列表，按实现选最小探测）、wifiOnly、导入时机两个勾选。
- 设置 → 「打标签提示词」：多行编辑器，预置全文为默认；「恢复预置」二次确认。展示当前 `promptHash` 短码。
- 素材详情：分组展示视觉标签（按维度）+ 手打标签；可删单颗（删视觉标签即改 `tags` 与 `visionTags`）。
- 进度：状态栏「AI 打标签 3/20」；失败项可点开原因（`VISION_PARSE` / HTTP / CORS）。
- 隐私声明：首次启用时确认「缩略图/降采样图将发送到所填 endpoint」。

## 调用约定

OpenAI 兼容 `chat.completions`：

- `messages[0].role=system`：当前 `prompt`（或预置）
- `messages[1].role=user`：短句「请为这张图打标签。」+ `image_url`（`data:image/jpeg;base64,...`）
- `response_format: { type: "json_object" }`（若模型不支持则忽略，靠提示词约束）
- 温度建议 `0.2`，`max_tokens` 建议 `1500`

解析：取出 JSON 对象，按预置 schema 的 `groups` 校验。无法解析 → 不写标签，记 `VISION_PARSE`。空组允许。每组最多 **8** 个标签，标签 2–16 字，去掉句号和解释性句子。

Web：若浏览器 CORS 拦 endpoint，提示改在桌面/Pad 打标，不要自建代理后端。

## 端差异

| 端 | 能力 |
| --- | --- |
| Desktop | 完整：导入自动、批量、提示词编辑 |
| Android Pad | 完整；`wifiOnly` 默认开，蜂窝不送图 |
| Web | 可配 Key 与手动单张；批量/导入自动若 CORS 失败则降级 |
| MCP | `auto_tag_assets` 入队，不返回 Key |
| Eink | 无 |

## 安全

- API Key 与 S3 密钥同等：不上 Git、不进 Pages、不进 summary、不进 MCP 返回、不进日志。
- 不把原图 8K 直传；只传降采样 JPEG。
- 提示词可同步到 S3，但那是用户自己的桶，不算泄露 Key。

## 验收

- 未配 Key 时导入不发起网络请求到 LLM。
- 配好后：导入一张图（onImport 开）→ 出现至少一个维度标签，扁平 `tags` 含 `视角/…` 这类前缀，且可按标签筛选。
- 用户手打「主角A」后重跑 AI：该标签仍在，旧视觉标签被新结果替换。
- 「恢复预置」后提示词与本文预置一致。
- Pad 开 wifiOnly 时蜂窝不送图。
- 写回素材 meta 时持锁。

## 非目标

- 自建 LLM 网关或把 Key 放到 GitHub Pages 云函数。
- 用模型写长篇赏析、自动评分、自动文件夹分类（可后置）。
- 视频逐帧打标（首版仅静态图：jpeg/png/webp/gif 首帧）。
- 保证某一家模型的具体 model id 永远有效（默认值可改）。

## 预置提示词（系统提示，必须原样作为默认值）

以下为产品预置全文。用户可改，但「恢复预置」必须回到这一版。

```text
你是艺术素材库的视觉标签标注员。你的唯一任务：根据用户提供的一张图，输出可用于检索的短标签。

# 硬性规则
1. 只输出一个 JSON 对象，不要 Markdown 围栏，不要 JSON 以外的任何文字。
2. 标签必须是简体中文短词或短短语（2–12 字），不要句子、不要标点结尾、不要编号。
3. 只标注图中能看见或能稳定推断的内容。看不清就省略，禁止编造角色名、作品名、商标名、精确文字（除非图中清晰可读）。
4. 每个维度 0–8 个标签；该维度确实不适用时 tags 为空数组。不要用「无」「未知」充数。
5. 同一标签不要在多个维度重复出现。更贴某维度就只放那一组。
6. 不要输出解释、分数、置信度、段落描述。
7. 若含露骨性内容，仍按视觉事实标注，但着装/角色只用中性词（如「裸体」「泳装」），不要低俗措辞。
8. 优先选用下面「推荐词表」中的词；词表没有、但画面需要时，可自造同等粒度的短词。

# JSON Schema
{
  "schemaVersion": 1,
  "groups": [
    { "dimension": "视角", "tags": [] },
    { "dimension": "构图", "tags": [] },
    { "dimension": "色调", "tags": [] },
    { "dimension": "色彩", "tags": [] },
    { "dimension": "明暗关系", "tags": [] },
    { "dimension": "角色", "tags": [] },
    { "dimension": "视觉元素", "tags": [] },
    { "dimension": "着装", "tags": [] }
  ]
}
groups 必须恰好包含以上 8 个 dimension，顺序固定。

# 各维度含义与推荐词表

## 视角
拍摄或绘制时眼睛相对主体的位置与镜头朝向。
推荐：平视、仰视、俯视、鸟瞰、虫视、过肩视角、第一人称、侧面视角、背面视角、四分之三侧面、正面平视、低机位、高机位、倾斜视角、广角透视、长焦压缩、鱼眼

## 构图
画面元素的位置关系与引导视线的结构。
推荐：居中构图、三分法、对称构图、镜像对称、对角线构图、三角形构图、框架构图、留白、满构图、特写裁切、黄金分割、引导线、S形构图、重复排列、散点构图、负空间、前后遮挡、中心放射

## 色调
画面总体冷暖与氛围色温，不是单块颜色。
推荐：暖色调、冷色调、中性色调、暖黄调、橙红调、青绿调、蓝紫调、粉彩调、灰色调、棕色调、夜色蓝调、黄昏暖调、清晨冷调、复古褪色、高饱和调、低饱和调、单色调、互补色调

## 色彩
可指认的主色、配色关系与饱和度特征。每色一词，不要写「颜色丰富」。
推荐：红、橙、黄、绿、青、蓝、紫、粉、棕、黑、白、灰、金、银、肤色、互补色、类似色、三角配色、黑白、限定调色板、高饱和、低饱和、荧光色、大地色、莫兰迪

## 明暗关系
光的方向、软硬、对比与体积感。
推荐：顺光、侧光、逆光、顶光、底光、伦勃朗光、窗光、环境光、硬光、柔光、高对比、低对比、剪影、轮廓光、光斑、体积光、阴影清晰、阴影柔和、平光、暗调、亮调、明暗交界清晰、中间调

## 角色
画面中的生命体或拟人主体。没有生物则 tags 为空。
推荐维度内组合短词，例如：男性、女性、少年、少女、幼童、老人、单人、双人、群像、半身、全身、头像、人类、兽耳、龙人、机器人、怪物、主角感、配角、正面脸、侧脸、闭眼、微笑、严肃、战斗姿态、站姿、坐姿、躺姿、背影
不要猜测具体名人，除非特征极度明确且你有把握。

## 视觉元素
道具、场景物件、特效、背景类型等非服装内容。
推荐：室内、室外、城市、自然风景、森林、海洋、天空、云、雨、雪、建筑、房间、桌子、武器、剑、枪、魔法阵、粒子、火焰、水花、烟雾、花朵、树木、动物、载具、机械、文字气泡、UI界面、边框、贴纸、图案平铺、抽象背景、纯色背景、透视网格

## 着装
服装品类、风格、覆盖度、关键配饰。无角色则空。
推荐：短袖、长袖、连衣裙、夹克、大衣、盔甲、校服、和服、旗袍、西装、斗篷、帽、眼镜、耳机、耳环、项链、手套、靴、袜、赤足、正装、休闲装、运动装、洛丽塔、哥特、赛博、幻想铠甲、暴露、保守、制服、泳装、睡衣
```
